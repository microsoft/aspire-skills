# Go AppHost Authoring

Patterns for editing `apphost.go`. Go AppHosts need **Aspire 17.0 or later** and Go 1.26 or
later on `PATH` (https://go.dev/dl/). **Never edit `.aspire/modules/`** - it is generated and
any change is clobbered. On older Aspire versions keep the AppHost in C# or TypeScript.

> Look up unfamiliar API: `aspire docs api search <query> --language go`
> then `aspire docs api get <id>`. If the search finds nothing, find the signature in the
> generated SDK instead of guessing: `grep -n "AddGoApp" .aspire/modules/aspire.go` (read-only).

## Detect and Scaffold

A Go AppHost is an `apphost.go` next to an `aspire.config.json` whose `appHost.language` is
`go`, plus a root `go.mod` with `replace apphost/modules/aspire => ./.aspire/modules`. A Go
*service* inside a C# or TypeScript AppHost does **not** make that AppHost a Go AppHost: keep
authoring `apphost.cs` / `apphost.mts` and wire the service with `AddGoApp` (see
`apphost-wiring.md`).

| Goal | Command |
|------|---------|
| Go API + Redis starter | `aspire new aspire-go-starter` |
| Empty Go AppHost | `aspire new aspire-go-empty` |
| Add an AppHost to an existing repo | `aspire init --language go` |

## Hard Refusal: `.aspire/modules/` Is Off-Limits

`.aspire/modules/` (`aspire.go`, `base.go`, `transport.go`, `go.mod`) is the generated Go SDK.
`aspire add`, `aspire restore`, and `aspire run` / `aspire start` regenerate it, so hand edits
are lost. If asked to edit it - however the request is phrased - refuse and redirect:

```text
I won't edit files in .aspire/modules/ - that directory is generated by the Aspire CLI and
any edits are overwritten on the next `aspire add` / `aspire restore` / `aspire start`.
Make the change in apphost.go instead. To add an integration, run
`aspire add <integration>` and Aspire regenerates the SDK.
```

## Skeleton

Copied from `aspire new aspire-go-starter`:

```go
package main

import (
	"log"

	"apphost/modules/aspire"
)

func main() {
	builder, err := aspire.CreateBuilder()
	if err != nil {
		log.Fatal(aspire.FormatError(err))
	}

	// A Redis cache the API will use for read-through caching.
	cache := builder.AddRedis("cache")

	// The Go HTTP API. WithModTidy runs "go mod tidy" before launching so that
	// go.sum is always up to date. Aspire injects:
	//   - "ConnectionStrings__cache" so the API can dial Redis.
	//   - "OTEL_EXPORTER_OTLP_*" env vars (via WithOtlpExporter) so traces,
	//     metrics, and logs flow to the Aspire dashboard.
	api := builder.AddGoApp("api", "./api").
		WithModTidy().
		WithReference(cache).
		WaitFor(cache).
		WithHttpEndpoint(&aspire.WithHttpEndpointOptions{Env: aspire.StringPtr("PORT")}).
		WithExternalHttpEndpoints().
		WithOtlpExporter()

	// Each call records its failure on the handle that it returns, so check every resource.
	for _, resource := range []aspire.Resource{cache, api} {
		if err := resource.Err(); err != nil {
			log.Fatal(aspire.FormatError(err))
		}
	}

	app, err := builder.Build()
	if err != nil {
		log.Fatal(aspire.FormatError(err))
	}
	if err := app.Run(); err != nil {
		log.Fatal(aspire.FormatError(err))
	}
}
```

## Handles and Deferred Errors

`Add*` and `With*` calls do not return `(value, error)`. They return a handle and record a
failure on it:

- The first error wins and later calls on a failed handle short-circuit. Read it with `Err()`.
- Checking the last handle of a fluent chain covers every call in that chain.
- `Build()` returns only the **builder's own** error and never inspects resource handles. Check
  `Err()` on every resource you declare before calling it, as the skeleton does.
- Methods that return `error` directly (`Build`, `Run`) are checked with `if err != nil`.
- Print errors with `aspire.FormatError(err)`: it expands `*aspire.CapabilityError` (message,
  code, capability, parameter details) and falls back to `err.Error()`. Use `errors.As` for the
  pieces:

```go
var capErr *aspire.CapabilityError
if errors.As(err, &capErr) {
	log.Printf("capability %s failed: %s", capErr.Capability(), capErr.Message())
}
```

## Options Structs

Required parameters are positional. Optional ones go in a trailing options struct whose fields
are pointers, built with `aspire.StringPtr`, `aspire.IntPtr`, `aspire.BoolPtr`, and
`aspire.Float64Ptr`. Numeric fields such as ports are `*float64`; slice fields are plain slices.

```go
api := builder.AddGoApp("api", "./api", &aspire.AddGoAppOptions{
	PackagePath: aspire.StringPtr("./cmd/server"),
	BuildTags:   []string{"netgo"},
}).
	WithModTidy().
	WithHttpEndpoint(&aspire.WithHttpEndpointOptions{Port: aspire.Float64Ptr(8080)})
```

## Go Apps: `AddGoApp`

`AddGoApp(name, appDirectory, options...)` comes from `Aspire.Hosting.Go`, available from Aspire
13.4 in a C#, TypeScript, or Go AppHost (Go AppHosts themselves need 17.0).

- `appDirectory` is relative to the AppHost directory. It is the Go module root (where `go.mod`
  lives) and the Docker build context for `aspire publish`, which generates a Dockerfile unless
  `appDirectory` already has one.
- `PackagePath` (default `.`) selects the main package, for example `./cmd/server`. Other
  options: `BuildTags`, `LdFlags`, `GcFlags`, `RaceDetector`.
- It already requires `go` on `PATH`, enables the OTLP exporter, and adds VS Code debugging.
- `WithModTidy()` (the scaffold default), `WithModDownload()`, and `WithModVendor()` run
  `go mod tidy`, `go mod download`, and `go mod vendor` before the app starts; `WithVetTool()`
  runs `go vet ./...`. All four apply in run mode only.
- The service reads its configuration from the environment. For example, `WithReference(cache)`
  on a Redis resource injects `ConnectionStrings__cache`, and `Env: aspire.StringPtr("PORT")`
  on `WithHttpEndpoint` puts the assigned port in `PORT`.

## Packages and the Generated SDK

`AddGoApp`, `AddRedis`, and every other integration method exist in `.aspire/modules/` only
after their package is added:

```bash
aspire add go      # Aspire.Hosting.Go; the name is the package id without "Aspire.Hosting."
aspire add redis
aspire restore --apphost apphost.go
```

`aspire add` records the package under `packages` in `aspire.config.json` and regenerates the
SDK. `aspire restore` regenerates it from that file: run it after cloning, switching branches,
hand-editing `packages`, and in CI before `go build` / `go vet`. Without `.aspire/modules/`, Go
fails with `replacement directory ./.aspire/modules does not exist`. `.aspire/` is gitignored.

## Run and Validate

```bash
aspire restore --apphost apphost.go    # regenerate the SDK
go vet .                               # compile-check apphost.go against it
aspire start --non-interactive --format Json
aspire wait <resource-name>            # repeat per resource
aspire describe --format Json --include-hidden
aspire stop
```

Never start the AppHost with `go run .`. `aspire.CreateBuilder()` needs the
`REMOTE_APP_HOST_SOCKET_PATH` variable that only the Aspire CLI sets, so it fails with
"REMOTE_APP_HOST_SOCKET_PATH environment variable not set". See `validation.md` for the full
flow and the hand-off to `aspire-orchestration`.

## Hard Rules

1. Edit `apphost.go` only; never `.aspire/modules/`.
2. Check `Err()` on every resource before `Build()`.
3. Run the AppHost with `aspire start --non-interactive` or `aspire run`, never `go run .`.
4. Use first-party `AddGoApp` (`Aspire.Hosting.Go`, Aspire 13.4 or later). The Toolkit
   `AddGolangApp` is for Aspire older than 13.4 or an AppHost that already uses it; never swap it
   on your own.
5. Pass optional parameters in options structs built with the `aspire.*Ptr` helpers.
6. Look up any method you have not seen (API search, then the generated SDK); do not guess names.
